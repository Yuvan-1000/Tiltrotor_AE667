# Tiltrotor Helicopter — Milestone 2 Code Package

AE 667 Rotary-Wing Aerodynamics — Milestone 2: **Edgewise Flight, Cyclic Control, and Trimmed Conversion**

This package is organized by the **Milestone 2 task list (Tasks 1–10)**. It keeps only the Milestone-1 axial BEMT backend needed as a regression/limiting-case dependency, then contains the complete Milestone-2 implementation for Tasks 1–10. No Milestone-1 mission-planner package or unrelated project material is included.

## Quick start

Use Python 3.10+ with NumPy and Matplotlib.

```bash
python run_m2_all.py
```

The driver regenerates the figures/tables in `figures/` and `outputs/`; then run `python package_audit.py` and the two scripts in `tests/` for the required package checks.

Individual task drivers can also be run directly:

```bash
python task1_coordinate_systems.py
python task2_updated_algorithms.py
python task3_forward_flight_physics.py
python task4_rotor_forces_moments.py
python task5_control_response.py
python task6_aircraft_aerodynamic_model.py
python task7_trimmed_flight.py
python task8_conversion_corridor.py
python task9_mission_planner_v2.py
python task10_design_refinement.py
```

## Package structure

- `bemt_solver.py` — Milestone-1 axial BEMT backend retained for regression and limiting-case recovery.
- `edgewise_bemt.py` — azimuth-resolved M2 extension with non-uniform Glauert/Drees inflow, cyclic pitch, reverse-flow flagging, Mach/stall checks and rotor/body loads.
- `aircraft_config.py` — single source of truth for rotor, airframe, propulsion, mass and control limits.
- `aircraft_model.py` — explicit wing, tail, fuselage/nacelle and twin counter-rotating rotor aircraft-load model.
- `trim_solver.py` — bounded steady-trim solver with all six aircraft load residuals.
- `mission_planner_v2.py` — generic state/mass/fuel/time-step mission engine.
- `task1_...` through `task10_...` — one runnable driver for each M2 task, with report-section outputs included where applicable.
- `inputs/` — aircraft configuration, control-sweep conditions, trim matrix and outbound/inbound mission examples.
- `data/` — validation data and M1 regression reference values.
- `figures/` — graded/report figures generated by the task scripts.
- `outputs/` — CSV tables, operating-condition notes, physical interpretations and test summaries.
- `tests/` — M1 regression and M2 smoke tests.

## Important conventions

Aircraft body axes are +X forward, +Y starboard, +Z down. Nacelle angle γ=90° is helicopter mode and γ=0° is airplane mode. Rotor +z is the thrust direction. Positive azimuth follows the rotor rotation sense and ψ=90° is the advancing side for the representative rotor.

The pitch convention used here is

`θ(ψ) = θ0 + θ1c cos(ψ) + θ1s sin(ψ)`

with **θ1c = lateral cyclic** and **θ1s = longitudinal cyclic**, matching the Blade Dynamics lecture.

## Model limitations carried into M2

The rotor is treated as a rigid disk with no blade flapping. Reverse-flow elements are flagged and excluded from the forward-flow polar calculation. Stall is flagged, not dynamically modeled. The airfoil remains a linear lift / parabolic drag model. Rotor wake/wing interference, dynamic stall, realistic Reynolds/Mach-dependent polars, sideslip and transient flapping dynamics are not modeled and are listed as Milestone-3 improvements.

The wing/empennage model is deliberately preliminary and is used to make the transition/trim problem explicit rather than to claim high-fidelity aircraft prediction.

## Reproducibility notes

All aircraft/rotor values used by the task drivers are imported from `aircraft_config.py`. Mission sequences are read/generated as JSON input. No single aircraft or single mission is embedded in the mission engine. Numerical convergence, physical-feasibility checks and the M1 limiting cases are explicitly tested.

## Milestone-1 feedback carried into M2

1. The gross mass, empty mass, payload and fuel values are sourced from one configuration so report/code cannot disagree.
2. Algorithm diagrams are accompanied by written explanations.
3. Every graded edgewise plot states the operating condition in its title and/or output note.
4. Cyclic-response plots include physical interpretation, not just curves.
5. The M1 cruise-range feedback is retained as a sanity/regression check using a speed-dependent drag calculation whose range curve peaks and then decreases at high speed.
